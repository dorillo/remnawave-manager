# Исходящий IP сайта-заглушки

Если сервер имеет несколько IPv4, сайт может принимать посетителей через новый
адрес, но получать ленту со старого. Выбор IP для сайта задаёт исходящий локальный
IPv4 внешним запросам nginx: ленте, поиску, комментариям и проксируемым изображениям.

В меню: **Сайты-заглушки Node → Исходящий IP сайта**. Доступны текущая настройка,
проверка источника через выбранный адрес и смена IP. В списке — IPv4 активных
интерфейсов; типичные адреса Docker, WARP и туннелей исключены. Режим `auto`
возвращает стандартный выбор исходящего адреса.

```sh
sudo rwm disguise egress status
sudo rwm disguise egress check 31.76.66.161
sudo rwm disguise egress set 31.76.66.161
sudo rwm disguise egress set auto
```

Для автоматизации поддерживаются `--json` (глобальный флаг) и `--yes`:

```sh
sudo rwm --json disguise egress status
sudo rwm disguise egress set 31.76.66.161 --yes
```

## Проверка и применение

1. Проверяются inventory, неизменность управляемых конфигураций, bind mounts сайта,
   наличие IPv4 и режим `network_mode: host` у nginx.
2. Через выбранный адрес выполняется ограниченный по времени HTTPS-запрос к
   источнику установленного шаблона. Для Morrow проверяются две страницы ленты.
   Проверяется HTTP-ответ и формат данных; результат не является заключением
   о доступности всех сайтов или о блокировке IP.
3. Создаётся обычный backup менеджера, файлы проверяются повторно. В известные
   внешние маршруты сайта добавляется помеченная директива `proxy_bind`.
4. Изолированный `nginx -t` проверяет новую конфигурацию перед активацией.
   Контейнер nginx пересоздаётся для обновления bind-mounted файлов; возможен
   короткий перерыв запросов сайта. Другие контейнеры не перезапускаются.
5. Источник проверяется через локальный listener самого nginx. Для локального
   HTTPS-пробника проверка сертификата сайта отключена, соединение принудительно
   направлено на локальный socket/адрес. Сертификат внешнего источника nginx
   по-прежнему проверяет. При ошибке возвращаются прежние конфигурация и inventory.

При недоступности источника применение останавливается до изменения файлов.
Для восстановления `auto` при неисправном источнике или подготовки остановленного
nginx можно явно пропустить сетевые проверки:

```sh
sudo rwm disguise egress set auto --skip-check
```

Этот флаг сохраняет проверки локального IP, конфигурации и backup; доступность
ленты после применения не подтверждается. Обычное интерактивное меню всегда
использует сетевые проверки.

## Сохранение настройки и границы

Настройка хранится в управляемой nginx-конфигурации, входит в backup и её checksum
в inventory. Она сохраняется после перезагрузки, обновления менеджера и смены
любого из семи штатных шаблонов. Повторный выбор того же IP не пересоздаёт контейнер.
Если IP удалён с интерфейса, `egress status` и `rwm diagnose` показывают проблему.
Автоматического переключения на другой адрес нет.

Поддерживаются IPv4 и контейнерный nginx в host network. Для нескольких vhost
одного сайта выбор применяется согласованно. Изменённые вручную маршруты,
неоднозначные includes и пользовательский `proxy_bind` требуют предварительного
согласования конфигурации; менеджер их не перезаписывает.

Конфигурация Xray, DNS-записи, системные маршруты, firewall и настройки WARP этой
функцией не меняются. Привязка адреса не отменяет существующие policy routing или
NAT: если они мешают доступу, проверка завершится ошибкой. Выбор исходящего IP VPN
выполняется отдельно в профиле Xray панели Remnawave.

Видео, которое браузер получает напрямую с CDN (например, в Morrow), не проходит
через nginx и не меняет свой путь загрузки при выборе IP сайта.
