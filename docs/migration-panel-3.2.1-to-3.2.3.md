# Обновление Panel до 3.4.4

Менеджер проверяет и обновляет Panel до `3.4.4`, Subscription Page до `8.0.0` и PostgreSQL до `18.4` по digest из `compatibility.json`.

В Panel 3.4.0-3.4.1 добавлены штатные Prisma-миграции режимов привязки Host к Internal Squads и тегов сущностей. Новые параметры генерации short UUID имеют безопасные upstream defaults, поэтому существующий `.env` остаётся валидным. Panel 3.4.2 исправляет конкурентную регистрацию HWID, а 3.4.3 закрывает обход аутентификации backend-tools; в [3.4.4](https://github.com/remnawave/backend/compare/3.4.3...3.4.4) также нет новых миграций или обязательных ENV. Контракт API 3.4.4 — `@remnawave/backend-contract@3.4.15`. Миграции запускаются entrypoint Panel; вручную менять схему или `.env` не нужно. До остановки сервисов менеджер скачивает и проверяет все целевые образы. Затем останавливает Panel и Subscription Page, создаёт согласованный backup базы и конфигурации и только после этого переключает версии. При ошибке после изменения файлов восстанавливаются dump, конфигурация и прежние образы. После запуска проверяются Panel, Subscription Page, обязательные API scopes и nginx.

В Compose меняются только прямые `image` выбранных сервисов; домены, токен Subscription Page, CDN и пользовательские настройки сохраняются. Для старой Panel выполняется миграция известных ENV-ключей в формат v3; nginx получает штатные исправления gzip и совместимости. Managed nginx/env/site-файлы защищены от параллельных изменений drift-проверкой и хешами. Отдельные серверы Node с XHTTP stream separation, Reality и WARP эта операция не затрагивает. После запуска менеджер возвращает исходный набор running/stopped-сервисов.

Сначала установите обновлённый менеджер из этой версии репозитория (`sudo ./install.sh install`). Затем на сервере Panel выполните:

```bash
sudo rwm adopt --path /opt/remnawave --role panel
sudo rwm diagnose
sudo rwm backup create --reason before-panel-3.4.4
sudo rwm update --yes
```

Если исходный образ не доказан по digest или конфигурация изменилась после adoption, операция останавливается до любых изменений. Не используйте `--accept-unknown-source`, если источник нельзя независимо проверить.

Если диагностика обнаружила небезопасные права приватных managed-файлов, выполните `sudo rwm diagnose --repair-permissions`, затем повторите диагностику. Ручной backup выше — дополнительная копия: `update` создаёт собственный согласованный backup после остановки приложений.

После успешного обновления Panel можно обновлять менеджер и Node на каждом сервере ноды по [инструкции](update-node-3.0.0-to-3.1.1.md). Уже установленная Node 3.4.1 совместима с Panel 3.4.4; переустанавливать её из-за обновления панели не требуется. Обновление приложений само по себе не заменяет сайты-заглушки — для этого используется [управление сайтами](node-sites.md).
