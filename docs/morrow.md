# Морроу AI (`03-morrow-coffee`)

Статическое приложение без сборки и собственного сервера приложений. Шаблон
сохраняет прежний идентификатор и устанавливается штатной командой применения
сайта. Социальные сети и ленты публикаций не подключаются.

## AI-провайдер

Основной провайдер — **Prexzy AI Writer**:
`POST https://prexzyapis.com/ai/aiwriter-chat`, тело `application/x-www-form-urlencoded`
с параметром `prompt`. Ключи, cookies, токены и внешние SDK не используются.
Запросы отправляются непосредственно из браузера с `credentials: omit`.
История сериализуется в JSON внутри запроса вместе с инструкцией проекта,
настройками ответа и текстом явно выбранных файлов. Сайт никогда не отправляет
весь профиль или все файлы проекта автоматически.

Проверка 15 сентября 2026 года: реальный Chrome получил ответ `Vera` на вопрос об
имени из предыдущего сообщения. Проверены POST, CORS с отдельного origin и контекст.
Ответ имеет структуру `result.text: string[]`. Модель в проверенном ответе —
`gpt-4o-mini`; поставщик может изменить её без уведомления. Поэтому интерфейс
показывает название сервиса, а не обещает конкретную модель.

Проверенный `/ai/chatgpt` из примера главной страницы вернул 404; Qwen — пустой
ответ; DeepQuery — ошибку; Mistral — требование входа. Они не используются как
автоматические резервные endpoints. Pollinations в актуальной документации требует
авторизацию генерации и рекомендует OAuth/BYOP для новых браузерных интеграций.
Резервный провайдер сейчас не включён: при отказе запрос можно повторить вручную.

Документация поставщиков: [Prexzy](https://docs.prexzyapis.com/),
[каталог endpoints](https://docs.prexzyapis.com/endpoints),
[Pollinations](https://github.com/pollinations/pollinations/blob/main/APIDOCS.md).
Доступность из РФ подтверждена пользователем. Проверка рабочего окружения не
является измерением всех российских операторов или гарантией доступности API.

Предел контекста приложения — 24 000 символов. История не обрезается молча:
при превышении лимита предлагается новый диалог или уменьшение вложений.
Тайм-аут — 60 секунд, максимальный JSON-ответ — 1 МБ, текст ответа — 60 000
символов. HTTP 429 учитывает доступный браузеру `Retry-After`, иначе ждёт 30 секунд.
Потоковый вывод для этого endpoint не заявляется. Отмена прекращает браузерное
ожидание и исключает поздний ответ; остановка вычисления на стороне провайдера
не гарантируется. Автоматических повторов генерации нет.

## Возможности

- Диалоги с контекстом, поиском, закреплением, переименованием и удалением.
- Редактирование запроса с заменой последующей ветки, повтор последнего ответа,
  отмена и повтор неудачной генерации.
- Черновики, копирование, экспорт диалога в TXT/Markdown, таблицы и блоки кода.
- Профили, аватары с устройства, раздельные данные аккаунтов и удаление аккаунта.
- Проекты с описанием и инструкцией, перенос диалогов и файлов между проектами.
  При удалении проекта его материалы сохраняются без проекта.
- TXT, MD, CSV в UTF-8; просмотр, скачивание, выбор файлов для запроса.
- Импорт и экспорт профиля в JSON. Импорт заменяет рабочие данные после подтверждения;
  учётные данные и парольные хэши не экспортируются и не импортируются.
- Русский/английский интерфейсы, независимый язык ответа, три стиля ответа,
  светлая/тёмная/системная тема, мобильная навигация и reduced-motion.

Гость может вести диалог в памяти вкладки. Регистрация переносит гостевые диалоги
в созданный профиль; вход в существующий аккаунт открывает его сохранённые данные.
Нет публичных ссылок на переписку и межустройственной синхронизации.
PDF, изображения для AI, OCR и генерация изображений в этой версии не поддерживаются.
Аватары поддерживают PNG/JPEG/WebP до 5 МБ, затем перекодируются в JPEG 160×160.

## Данные и безопасность

`IndexedDB` (`morrow:workspace:v1`) содержит отдельные stores `accounts` и
`workspaces`. Рабочие данные привязаны к случайному идентификатору аккаунта.
Транзакционная запись проверяет существование аккаунта и ревизию данных:
устаревшая вкладка не перезаписывает изменения другой вкладки. При конфликте
пользователю предлагается перезагрузить страницу. После отказа записи рабочее
состояние не выдаётся за сохранённое. Полученный, но не записанный AI-ответ
остаётся доступен для копирования и повторного сохранения до закрытия страницы.

Сессия хранится в `sessionStorage`, а пароль — как PBKDF2-SHA-256, 210 000 итераций
и случайная соль 16 байт. Это разделение данных приложения, не серверная граница
безопасности: доступ к DevTools/профилю браузера позволяет читать или менять базу.
Переписка не шифруется. Очистка данных сайта удаляет аккаунты и материалы.

Ограничения на один профиль: 16 МБ JSON, 200 диалогов, 500 сообщений на диалог,
100 проектов, 100 файлов. Один файл — до 256 КБ; одно сообщение может содержать
до 10 выбранных файлов. Вложения сохраняются снимками внутри сообщений, поэтому
удаление оригинального файла не меняет прошлый контекст разговора. Снимки учитываются
в общем лимите хранилища. Браузер может отказать в записи раньше собственного лимита.

Импорт проверяет версии, размеры, типы, идентификаторы, дубликаты, ссылки проектов
и схему данных; из входных объектов реконструируются только разрешённые поля.
Ответы AI и файлы отображаются через текстовые DOM-узлы. Markdown допускает
ограниченное форматирование и только HTTPS-ссылки без credentials. HTML не
исполняется, изображения из ответов не загружаются, код не запускается.

## Модули

| Файл              | Назначение                                            |
| ----------------- | ----------------------------------------------------- |
| `app.js`          | Маршруты, экраны и пользовательские действия          |
| `morrow-ai.js`    | Контракт провайдера, контекст, запрос, отмена, лимиты |
| `morrow-auth.js`  | Регистрация, вход, хэш пароля и сессия                |
| `morrow-db.js`    | IndexedDB и транзакции                                |
| `morrow-store.js` | Схема, валидация, очередь записей, импорт и экспорт   |
| `morrow-files.js` | Чтение файлов, аватары и скачивание                   |
| `morrow-ui.js`    | DOM, диалоги, безопасный Markdown                     |
| `morrow-i18n.js`  | RU/EN и форматирование дат                            |

Новый AI-адаптер должен сохранить контракт `generate({prompt, signal})`, возвращать
текст и нормализованные ошибки. `buildContext` можно заменить на структурированные
messages без изменения хранилища переписки. `site-runtime.js` не подключается.

## Менеджер, CSP и упаковка

HTML разрешает соединения только с собственным origin и `prexzyapis.com`.
`NODE_CSP` включает этот origin для новых установок. Применение Morrow обновляет
только известные точные политики в неизменённых управляемых конфигурациях nginx.
Произвольные политики оператора не переписываются; их совместимость нужно проверить
самостоятельно. Предыдущая CSP Aster и её nginx-маршрут сохраняют совместимость.
Morrow не добавляет прокси. Файлы сайта и политика откатываются вместе при ошибке
активации nginx, контрольные суммы inventory обновляются после успешной установки.

Все модули попадают в существующие package-data шаблоны `*.js`; новые зависимости
приложению не нужны. Обновление ранее установленного сайта должно включать и HTML,
и CSP nginx: изменение только meta-тега не отменяет ограничений HTTP-заголовка.

## Проверки

Из корня проекта:

```powershell
$env:PYTHONPATH = 'src'
python -m unittest discover -s tests -q
node tests/morrow.browser.cjs
```

Браузерный тест использует установленный Chrome и `playwright-core` из `tests/.tmp`.
Если зависимости ещё нет:

```powershell
npm install --prefix tests/.tmp --no-save --no-package-lock playwright-core@1.63.0
```

Другой Chromium можно выбрать переменной `MORROW_BROWSER`. Тест перехватывает
статические файлы в памяти и применяет серверную CSP; сервер просмотра не запускает.
Реальная проверка провайдера:

```powershell
$env:MORROW_LIVE = '1'
node tests/morrow.browser.cjs
Remove-Item Env:MORROW_LIVE
```

Браузерные сценарии проверяют аккаунты, контекст, файлы, проекты, импорт/экспорт,
отмену, 429, пустой ответ, сетевую ошибку, отказ IndexedDB, конфликт ревизий,
тайм-аут, сохранение ответа после отказа записи, черновики после перезагрузки,
переключение диалога/аккаунта во время запроса, удаление аккаунта,
безопасный вывод, RU/EN, темы и ширины 320–1440 px. Проверки не заменяют испытания
на физических мобильных устройствах, в Safari/Firefox и на установленном nginx.
