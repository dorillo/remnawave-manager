# Астер Видео (`02-aster-observatory`)

Статическая видеотека без сборки, серверного приложения и секретных ключей.
Публичные API и изображения доступны через фиксированные маршруты nginx.
Воспроизведение выполняет официальный встроенный плеер RUTUBE. NASA и PeerTube
не используются. Шаблон сохраняет прежний идентификатор и устанавливается
штатным механизмом менеджера.

## Источник и проверенные ограничения

Проверка 14 сентября 2026 года:

- RUTUBE `/api/video/person/{id}/?page=1` возвращает метаданные открытых каналов
  без токена при обычном HTTP-запросе. У проверенных ответов отсутствует
  `Access-Control-Allow-Origin`; прямой `fetch` с домена сайта отклоняется Chrome.
- Актуальная страница поиска вызывает
  `/api/search/video/?query=…&client=wdp`. Запрос
  `minecraft` без токена вернул 95 результатов и ссылку на следующую страницу.
  Ответ не содержит `Access-Control-Allow-Origin`: проверка с origin ASTER в
  Chrome завершилась `Failed to fetch`, хотя тот же запрос на странице RUTUBE
  получил HTTP 200.
- Документированный поиск VK Видео предполагает access token. Не используются
  извлечение внутренних анонимных токенов, чужие ключи, JSONP, отключение TLS
  или публичные CORS-прокси.
- В реальном Chrome загрузились шесть проверенных обложек с `pic.rtbcdn.ru`,
  открылась страница плеера и воспроизводилось видео
  `88ddc2aae5076fa8354c8ed7220ef89a`: `readyState=4`, время увеличилось до 5 секунд,
  ошибка HTMLVideoElement отсутствовала. Получены события готовности,
  состояния и позиции плеера.
- Это проверка из доступного рабочего окружения, а не измерение всех российских
  операторов. Региональные ограничения, реклама, удаление роликов и изменения
  API контролируются RUTUBE. Гарантировать доступность каждого видео нельзя.

Документация: [плеер RUTUBE](https://rutube.ru/info/embed/),
[поиск VK](https://dev.vk.com/ru/method/video.search),
[официальный SDK VK](https://github.com/VKCOM/vk-java-sdk/blob/master/sdk/src/main/java/com/vk/api/sdk/queries/video/VideoSearchQueryWithExtended.java).

## Режим каталога

Основной надёжный сценарий — реальная редакционная подборка в
`data/catalog.json`, загружаемая браузером с собственного домена. Источник —
анонимная общая выдача главной RUTUBE `/api/v2/video/recommendation/main`.
Тематический отбор по трём каналам удалён. Сохраняется порядок рекомендаций
поставщика; состав может отличаться от персональной главной пользователя.
Названия, даты, длительности, просмотры, обложки и аватары взяты из ответов
RUTUBE. Реальное число лайков загружается из публичного endpoint
`/api/numerator/video/{id}/vote`; реакция профиля Астер добавляется к нему только
в текущем интерфейсе и не отправляется на RUTUBE.

При поисковом запросе ASTER обращается к актуальному поисковому API RUTUBE через
узкий same-origin маршрут nginx `/_aster/rutube-search` и поддерживает до 20 его
страниц. Полученные ролики открываются во внутреннем плеере и догружаются кнопкой
«Загрузить ещё видео». Если RUTUBE или маршрут недоступен, поиск автоматически
продолжает работу по домашней выдаче и всем сохранённым канальным страницам.
Интерфейс принимает до 5000 уникальных видео и выводит резервные результаты
порциями по 24 карточки.
Для каждого присутствующего в ней канала снимок отдельно сохраняет все страницы,
которые отдаёт публичная канальная выдача RUTUBE — сейчас до 10 страниц и 200
роликов на канал.
Резервный сценарий — **не поиск по всему RUTUBE** и не непрерывно обновляемая
публичная лента.
Служебная подпись о снимке в пользовательском интерфейсе не показывается.
Актуальность данных задаёт дата подготовки `catalog.json`: прямое обновление
из открытой страницы невозможно из-за отсутствия CORS у API RUTUBE.

Для обновления файла из корня исходного проекта:

```powershell
python scripts/update_aster_catalog.py
```

`update_aster_catalog.py` запускает `scripts/fetch_aster_feed.cjs`, который
запрашивает общую выдачу без ограничений по темам: чистый анонимный Chrome
открывает главную RUTUBE и получает публичный JSON. Нужны Chrome и
`playwright-core` из команды установки зависимостей ниже. Никакие токены не
извлекаются; браузер и сайт посетителя не используются как прокси.
Chrome обнаруживается автоматически в Windows, macOS и Linux; нестандартный путь
можно задать переменной окружения `ASTER_BROWSER`. Также поддерживается Chromium,
установленный Playwright. Эти два скрипта нужны для подготовки нового каталога;
`preview_aster.py` использует готовый файл и не запускает их.
Возможен импорт полного результата `fetch_aster_feed.cjs` через `--input файл.json`;
обычный ответ только домашней выдачи отклоняется, чтобы случайно не удалить
каналы, лайки и комментарии из снимка.
Скрипт отбрасывает платные, клубные, удалённые, скрытые, отмеченные взрослые
материалы и трансляции. Домашний каталог ограничен 480 видео, канальная выдача —
200 видео на канал. При отказе или пустом ответе прежний файл сохраняется.
Запись атомарная.
Скрипт запускается при подготовке обновления сайта, постоянный сервис не нужен.
Для доставки обновлённого файла используется обычное применение шаблона;
ручные изменения установленного сайта должны учитываться через штатный adoption.

В тот же снимок для каждого домашнего видео попадает до четырёх страниц публичного
обсуждения из `/api/v2/comments/video/{id}/`; для нескольких веток дополнительно
загружаются ответы. Интерфейс раскрывает их десятками по кнопке «Показать ещё
комментарии». Точное число зависит от текущей выдачи RUTUBE; оно проверяется при
обновлении и покрыто тестом. Сохраняются текст, автор, аватар,
дата, лайки, закрепление и связь ответа с родительским комментарием.
HTML из ответа не используется. Общий счётчик отражает значение RUTUBE.

При открытии видео обсуждение обновляется через фиксированный маршрут
`/_aster/rutube-comments/{id}`. Снимок служит резервом при недоступности источника;
при успешном ответе старые комментарии заменяются свежими. Описание ролика и
профиль канала загружаются через `/_aster/rutube-video/{id}` и
`/_aster/rutube-profile/{id}`. Напрямую к этим API браузер не обращается.

Запросы имеют тайм-аут и отменяются при смене страницы. Сохранённый
браузером каталог используется при отказе сайта до семи дней. Видео и медиа
для офлайн-просмотра не скачиваются.

## Возможности

- Главная «Для вас» с общей сеткой рекомендаций и порционной загрузкой карточек.
- Каталог с поиском по названию, описанию и каналу, сортировкой, фильтрами
  длительности и языка, порционной загрузкой всего доступного канального снимка.
- Страница просмотра: RUTUBE iframe, описание, канал, похожие материалы,
  лайки, «Смотреть позже», копирование ссылки и комментарии.
- Публичные комментарии RUTUBE и комментарии профиля в одном дереве. Для авторов
  показываются аватары и относительное время публикации; имя открывает внутреннюю
  страницу пользователя. Можно отвечать на исходные и вложенные комментарии или
  поставить им реакцию внутри Астер; эти действия не отправляются на RUTUBE.
  Собственные комментарии поддерживают ответы, редактирование, удаление веток и
  реакции. Основное поле нового комментария остаётся на месте. Ответ или
  редактирование открывает отдельное компактное поле под выбранным комментарием;
  фокус на основном поле закрывает редактор ответа.
  Старые заметки сохранены как текст черновика формы; без действия пользователя
  в комментарии они не превращаются. Данные включены в экспорт/импорт библиотеки.
- Каналы и подписки с фильтрами «Все каналы» и по отдельным каналам, история,
  «Понравившиеся» и «Смотреть позже». В подписках следующие порции видео
  загружаются отдельной кнопкой. Раздел
  плейлистов удалён из интерфейса;
  старое поле сохраняется при чтении и экспорте для совместимости библиотек.
- Профиль с регистрацией/входом, именем, описанием, аватаром с оптимизацией
  до 256×256, подтверждением выхода; данные разных профилей разделены.
- Экспорт библиотеки без паролей и импорт с проверкой структуры и подтверждением
  замены. Добавление публичного RUTUBE-видео по проверенной ссылке.
- Русский и английский интерфейсы, автоопределение языка и сохранение выбора.
  Метаданные видео не переводятся автоматически; текущая подборка русскоязычная.
- Адаптивность от 320 px, клавиатурная навигация, нативные модальные диалоги,
  восстановление фокуса, reduced-motion, состояния загрузки, ошибки и пустые списки.

История записывается после фактического начала проигрывания. Позиция обновляется
не чаще раза в десять секунд, а также при паузе, уходе со страницы и скрытии вкладки.
Продолжение использует параметр `t` официального плеера. При завершении видео
следующий просмотр начинается сначала. События принимаются только от текущего
iframe и точного origin `https://rutube.ru`. При смене аккаунта позиция прежнего
профиля не записывается в новый.

## Файлы и безопасность

- `app.js`: маршруты, страницы и пользовательские действия.
- `aster-data.js`: проверка метаданных, запросы, каталог и ограниченный кэш.
- `aster-player.js`: плеер, проверка сообщений, сохранение позиции, очистка ресурсов.
- `aster-comments.js`: комментарии, ответы и реакции без перезагрузки плеера.
- `aster-store.js`: состояние профилей, атомарные изменения, проверка импорта.
- `aster-auth.js`: PBKDF2-SHA256 с индивидуальной солью, 210000 итераций, сессия.
- `aster-i18n.js`: переводы и форматирование дат/длительности.
- `aster-ui.js`: DOM-компоненты, диалоги, уведомления и экспорт.

Требуется HTTPS или доверенный localhost для Web Crypto. Профили хранятся в
`disguise:aster:state:v1` и не являются серверной аутентификацией: доступ к данным
браузера позволяет читать или изменять их. Очистка данных сайта удаляет профиль.
В продукте это объясняется в раскрываемом разделе «Данные профиля»; термин
«локальный аккаунт» не используется. Комментарии и реакции не публикуются на RUTUBE.

Внешние строки выводятся текстовыми DOM-узлами, HTML поставщика не вставляется.
Разрешены только проверенные RUTUBE ID, HTTPS-ссылки и два домена обложек.
Пароли не хранятся открытым текстом и не попадают в экспорт. Ошибка записи
не выдаётся за успешное сохранение. Произвольные URL источников, сторонние
скрипты, шрифты и `shared/site-runtime.js` не подключаются.

## CSP и установка

HTML разрешает `connect-src 'self' https://rutube.ru`, `frame-src https://rutube.ru`
и изображения с `pic.rtbcdn.ru` / `pic.rutube.ru` плюс собственные аватары.
Скрипты и стили разрешены только с собственного сайта.

Общая серверная политика вынесена в `site_policy.py`: генератор node nginx
сохраняет разрешения Northline и добавляет RUTUBE для API и iframe. Остальные
шаблоны дополнительно ограничивают возможности собственными meta CSP.

При применении Астер точная прежняя CSP, сгенерированная менеджером, обновляется
в неизменённых управляемых `.conf` внутри каталога установки. Туда же добавляется
фиксированный поисковый reverse proxy: только метод GET и только endpoint
`/api/search/video/` на `rutube.ru`; заголовки и cookie клиента
upstream не передаются, `Set-Cookie` ответа скрывается. Хэши и безопасные пути
проверяются до и после подготовки. Используются существующие backup,
проверка/активация nginx и rollback. При ошибке восстанавливаются сайт,
конфигурация nginx и inventory. Пользовательские CSP не переписываются: их
необходимо согласовать с политикой Астер отдельно. Простая замена HTML не может
ослабить более строгий HTTP-заголовок или добавить поисковый маршрут.

## Локальный просмотр

Обычный VS Code Live Server не подходит для проверки поиска: RUTUBE не
разрешает CORS, а встроенный reverse proxy Live Server сохраняет локальный
заголовок `Host`, из-за чего upstream отвечает HTTP 403. Кроме того, Live
Server внедряет inline-скрипт перезагрузки, который ожидаемо блокируется
строгой CSP шаблона.

Для локального просмотра используется небольшой инструмент без внешних
зависимостей. Он раздаёт только каталог ASTER и проксирует только GET-запросы
фиксированных маршрутов поиска, комментариев, метаданных видео и публичных профилей,
не передавая заголовки авторизации и cookie браузера. Описания и число подписчиков
загружаются при открытии видео или профиля. Произвольные адреса и параметры
для маршрутов метаданных запрещены; ответы не кэшируются:


```powershell
python scripts/preview_aster.py
```

После запуска сайт доступен на `http://127.0.0.1:5502/`. Порт можно изменить
аргументом `--port`. В production этот инструмент не используется: маршрут
создаётся конфигурацией nginx при применении шаблона через менеджер.

## Проверки без сервера просмотра

```powershell
$env:PYTHONPATH = 'src'
python -m unittest discover -s tests -q
npm install --prefix tests/.tmp --no-save --no-package-lock playwright-core@1.63.0
node tests/aster.browser.cjs
node tests/northline.browser.cjs
```

`ASTER_BROWSER` позволяет указать другой Chromium; по умолчанию используется
Chrome в Windows. Тесты подают файлы перехватом запросов, HTTP-сервер не запускается.
Проверяются обе CSP вместе, регистрация, неверный пароль, разделение профилей,
экспорт/импорт, история и возобновление, поддельные сообщения,
опасные URL, отказ CORS и хранилища. Проверка геометрии охватывает девять страниц
на ширинах 320, 360, 390, 720, 768, 1024, 1440 px в двух языках.

Для диагностического прогона с реальными внешними ресурсами:

```powershell
$env:ASTER_LIVE = '1'
node tests/aster.browser.cjs
Remove-Item Env:ASTER_LIVE
```

Этот прогон выводит результаты CORS, загрузки изображений, состояния реального
HTMLVideoElement и событий iframe. Скриншоты сохраняются в игнорируемую
`tests/.tmp`. Проверки не заменяют тесты Firefox/Safari, российских операторов
и установленного на production nginx. Развёртывание и сервер просмотра в рамках
реализации не запускались.
