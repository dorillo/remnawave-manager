# Проксирование данных сайтов 1–7

Запросы API выполняются через существующие маршруты nginx. Изображения Line,
Aster, Morrow, Spros и Svod загружаются через `/_images/<разрешённый CDN>/<путь>`.
Loop и Fokus сохраняют свои маршруты изображений `/_loop/media/` и
`/_fokus/media/`. Видео Morrow и встроенный плеер Rutube загружаются по прежней
схеме; Loop сохраняет существующее проксирование клипов.

Общие маршруты добавляются при применении любого из шаблонов 1–7, включая
повторное применение уже установленного шаблона. На работающем сервере нужно
обновить менеджер и повторно применить выбранный сайт штатным способом: простое
копирование HTML/JS не добавит маршруты nginx.

Список источников задан в `image_proxy.py` и `shared/image-proxy.js`.
Произвольные домены, нестандартные порты и URL с логином/паролем не допускаются.
Неизвестные внешние источники изображений не загружаются напрямую; при добавлении
CDN список нужно обновить в обоих файлах. Редиректы источников не передаются
браузеру и не выполняются прокси. Запросы изображений допускают только GET/HEAD,
не передают cookies/авторизацию посетителя, проверяют TLS источника и не сохраняют
ответы в кеше nginx (`proxy_cache off`, `Cache-Control: no-store`).

Разрешены пути с расширениями изображений, аватарки Mail `/pic` и формулы
Wikipedia. Доступ к произвольным API на разрешённом домене через `/_images/`
закрыт. Общая политика `proxy_policy.py` проверяет TLS для всех прокси сайтов,
отключает кеширование и запись ответов на диск, скрывает cookies и перенаправления
источника, игнорирует управляющие заголовки `X-Accel-*`. Ответы получают безопасный
Content-Type, `nosniff` и CSP sandbox, чтобы внешний источник не мог исполнить
HTML/JavaScript с origin сайта. Аватарки без расширения передаются как
`application/octet-stream`; браузер отображает их внутри `<img>`.

Известные предыдущие блоки nginx обновляются при повторном применении шаблона.
Изменённые вручную блоки не переписываются по приблизительному совпадению.
Источники используют фиксированные домены: DNS должен работать при проверке и
перезагрузке nginx. Доступность сервиса со стороны сервера, его лимиты и изменения
API остаются внешними зависимостями; проксирование само по себе их не устраняет.

Производственный сервер использует только статические файлы и nginx.
`image_preview.py` обслуживает аналогичные маршруты в локальных preview-скриптах;
для preview размер одного ответа ограничен 32 MiB.

Для просмотра из корня репозитория (Python 3.12+), каждый нужный сервер запускается
в отдельном терминале:

| Сайт | Команда | Адрес |
| --- | --- | --- |
| Line | `python3 scripts/preview_northline.py` | http://127.0.0.1:5501/ |
| Aster | `python3 scripts/preview_aster.py` | http://127.0.0.1:5502/ |
| Morrow | `python3 scripts/preview_morrow.py` | http://127.0.0.1:5503/ |
| Spros | `python3 scripts/preview_answers.py` | http://127.0.0.1:5504/ |
| Svod | `python3 scripts/preview_svod.py` | http://127.0.0.1:5505/ |
| Loop | `python3 scripts/preview_loop.py` | http://127.0.0.1:5506/ |
| Fokus | `python3 scripts/preview_fokus.py` | http://127.0.0.1:5507/ |

Остановка — Ctrl+C. Для другого порта используется `--port <номер>`.

При обновлении меняется версия всей цепочки JavaScript-модулей: HTML и импорты
получают общий параметр `v`, рассчитанный по содержимому файлов. Preview отдаёт
HTML/JS/CSS с `Cache-Control: no-store`, поэтому новая CSP не смешивается со старым
кодом прямой загрузки изображений. После изменения Python-скриптов нужно
перезапустить preview и обновить страницу.

Aster загружает публичные комментарии для открытого видео через
`/_aster/rutube-comments/<video-id>`, включая видео из поиска и каналов.
Следующие страницы и ответы загружаются по запросу. При ошибке источника
сохранённые комментарии остаются видны, а интерфейс предлагает повторить загрузку.
Комментарии к пользовательским локальным роликам остаются локальными.
