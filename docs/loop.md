# Loop — GIF, стикеры и реакции (`06-loop-archive`)

Полностью статическое приложение на HTML/CSS/JavaScript. В production нужны
только файлы сайта и существующий nginx. Дополнительных приложений, базы данных,
Node.js/Python-процесса или серверной авторизации нет.

## Возможности

- Популярные GIF, стикеры и клипы, поиск, популярные запросы, категории и пагинация.
- «Мои материалы»: загрузка своих GIF, стикеров (PNG/WebP/GIF/JPEG) и клипов
  (MP4/WebM), название, до 20 тегов и категория. Удаление владельцем.
  Ограничения на размер файла в приложении нет.
- GIF без видеоверсии, включая загруженные GIF-стикеры, открываются в стандартном
  видеоплеере браузера с паузой, перемоткой и полноэкранным просмотром. При первом
  открытии видеоверсия готовится в браузере за время примерно одного цикла GIF;
  последняя версия кэшируется в памяти. Исходный файл для скачивания и встраивания
  не меняется. Прозрачные участки видеоверсии отображаются на фоне плеера;
  прозрачность оригинала сохраняется. При выключенных анимациях автозапуска нет.
  Подготовка отменяется при переходе со страницы или скрытии вкладки; после
  возвращения во вкладку возобновляется с начала. Ошибку можно повторить кнопкой.
  Используются MediaRecorder (WebM/MP4), локальный GIF-декодер omggif и
  fix-webm-duration для корректной длительности и перемотки WebM.
- Одна строка поиска в шапке; Ctrl/Cmd+K переводит в неё фокус.
- Плотная кладка карточек по самой короткой колонке, с исходными пропорциями
  медиа и сохранением порядка клавиатурной навигации. Подписи поверх изображения:
  при наведении/фокусе на компьютере, постоянно на сенсорном экране.
- Карточка с отдельным hash-адресом, тегами, автором, похожими материалами,
  скачиванием и кнопкой «Поделиться» (копирование при отсутствии Web Share).
- Локальные аккаунты, понравившееся, создание/переименование/удаление коллекций,
  добавление и удаление материалов. Профиль позволяет изменить имя и удалить аккаунт.
- Русский и английский интерфейс, светлая и тёмная темы. Заголовки, теги,
  запросы и категории из источника не переводятся.
- Адаптация для телефона и широкого экрана. Диалоги работают с клавиатуры,
  закрываются по Esc и возвращают фокус. Поиск и маршрут сохраняются при смене темы/языка.
- Видео в галерее воспроизводится без звука в видимой области, останавливается
  при уходе из неё и скрытии вкладки. Пауза и prefers-reduced-motion показывают
  неподвижный кадр на canvas, поскольку WebP-превью gifs.ru тоже могут быть анимированы.

Комментарии и ответы намеренно отсутствуют. Загрузки на источник, фиктивной
модерации, генератора GIF и регистрации на gifs.ru нет.
Скачивание использует доступный оригинал через существующий медиа-прокси и
атрибут download, без download-токенов и авторизации источника. Если оригинала
нет, используется доступное видео или превью.
«Встроить» выдаёт экранированный HTML для img/video с именем скачанного файла,
копированием и ручным выделением при недоступности буфера обмена. Файл нужно
разместить рядом с HTML-страницей.

Лента, похожие и личные списки показывают до 48 материалов за действие.
Лента объединяет два запроса источника по 24; при ошибке повтор сохраняет уже
показанные карточки. После окончания выдачи кнопка догрузки исчезает.
На экранах до 800 px навигация закреплена снизу; карточки сохраняют пропорции
медиа, длинные подписи действий переносятся.

## Данные и аккаунты

Источник — анонимные маршруты сайта gifs.ru. Это внутреннее API сайта,
а не договор о доступе к коммерческому GIFS API; адреса, условия и лимиты
могут изменяться. Доступность источников проверяется с конкретной ноды.

Аккаунты, лайки, коллекции и свои файлы хранятся в IndexedDB `loop:gifs:v1`
(версия схемы 2, обновление сохраняет существующие данные); сессия —
в localStorage; язык, тема и пауза — в localStorage. Пароли хэшируются
PBKDF2-SHA256 с индивидуальной солью и 210000 итераций. Для входа нужен HTTPS
или localhost. Личные коллекции и лайки разделены по аккаунтам.

Это локальные профили, не защита от владельца браузера. Синхронизации между
устройствами и восстановления через почту нет. Очистка данных сайта удаляет
аккаунты и коллекции. В источнике никакие действия пользователей не записываются.
Удаление аккаунта очищает его лайки, коллекции, загруженные файлы и превью
одной транзакцией. Удаление отдельного материала также атомарно очищает его
файл, превью, лайки и ссылки в коллекциях.

Коллекции сохраняют метаданные и ссылки, не копии медиа. Собственные файлы
сохраняются отдельно в IndexedDB как Blob; временные blob-адреса создаются
заново после перезагрузки и не записываются в коллекции. API имеет
ограниченный кеш в памяти; сетевые ошибки, пустая выдача и удалённый материал
показываются разными состояниями. Недоступность источника не заменяется
демонстрационными материалами.

## Прокси и безопасность

| Локальный путь (префикс `/_loop/gifs/`) | Метод | Источник относительно `/api/v1/` |
| --- | --- | --- |
| `popular` | GET | `Popular` |
| `categories` | POST | `Community/GetCommunities` |
| `category` | GET | `Community/GetFiles` |
| `trending` | GET | `Tag/GetTrendingSearches` |
| `search-gif`, `search-sticker`, `search-clip` | POST | `Gif/GetGifs`, `Sticker/GetStickers`, `Loop/GetLoops` |
| `related-gif`, `related-sticker`, `related-clip` | POST | `Gif/GetRelated`, `Sticker/GetRelated`, `Loop/GetRelated` |
| `item/<id>` | GET | `File/FileById/<id>` |

POST здесь используется исключительно для чтения, как на самом сайте источника.
JSON передаётся без построения тела через строковую подстановку nginx-переменных;
размер тела ограничен 2 КиБ. Nginx проверяет метод и параметры GET, клиент —
структуру исходящих параметров. Nginx не является валидатором JSON.

Медиа доступны через `/_loop/media/<имя файла>` только на фиксированном
`media.gifs.ru`, с проверенным шаблоном имени и формата. Видео поддерживает
Range/If-Range, GET и HEAD. Прямых запросов браузера к CDN нет.

Upstream-хосты фиксированы; произвольный URL передать нельзя. Включены TLS/SNI
и проверка цепочки сертификатов (depth 3), таймауты и запрет переадресаций.
Cookies и Authorization пользователя не передаются; Set-Cookie и Location
источника скрываются. Маршрутов записи, авторизации или загрузки на gifs.ru нет.

CSP в HTML ограничивает соединения собственным origin; изображения и медиа
разрешают также blob: для локальных файлов. Исполнение загруженного кода не
разрешено: SVG/HTML не принимаются, сигнатура и декодирование файла проверяются.
Внешний текст вставляется через DOM textContent, без исполнения HTML;
адреса медиа проверяются до преобразования в локальные маршруты.

## Просмотр и применение

Live Server может показать оболочку, но не создаёт прокси. Из корня репозитория:

```sh
python3 scripts/preview_loop.py
```

Адрес: `http://127.0.0.1:5506/`. При необходимости: `--port 5516`.
Скрипт использует стандартную библиотеку Python, привязывается к localhost,
не сохраняет серверные аккаунты и разделяет список маршрутов с production-конфигурацией.
Остановка — Ctrl+C.

Штатное применение на node-сервере:

```sh
sudo rwm disguise apply 06-loop-archive
```

Прокси включается при применении шаблона через менеджер. Используются существующие
резервное копирование, проверка nginx и транзакционный откат. Повторное применение
не дублирует маршруты. Другие прокси сохраняются; неизвестные CSP не заменяются
вслепую, изменённые управляемые файлы проходят обычную проверку inventory.

## Проверки

```sh
TMPDIR=/private/tmp PYTHONPATH=src python3 -m unittest \
  tests.test_loop_integration tests.test_disguise_sites tests.test_disguise \
  tests.test_svod_integration tests.test_aster_integration \
  tests.test_morrow_integration tests.test_answers_integration \
  tests.test_northline_integration tests.test_packaging -q
node tests/loop.browser.cjs
UI_ENGINES=chromium node tests/site-chrome.browser.cjs
```

`TMPDIR=/private/tmp` нужен на macOS для существующих проверок путей без symlink;
на Linux используйте обычный временный каталог. Браузерные тесты используют
установленный Chrome и `tests/.tmp/node_modules/playwright-core`; путь к браузеру
Loop можно задать через `LOOP_BROWSER`.

Опциональная живая проверка с сетью:

```sh
node tests/loop.live.cjs
```

Она запускает preview на свободном порту и останавливает его в finally.

## Собственные материалы

Доступны только текущему локальному аккаунту в этом браузере, не публикуются
на gifs.ru или для других посетителей сайта. В общих лентах и поиске они
смешиваются с источником; фильтры учитывают тип, название, теги и категорию.
Похожие локальные материалы ранжируются по совпадению тегов. Для своей карточки
похожие из источника ищутся по первому тегу либо названию; локальный ID и файл
в API не отправляются. При недоступности источника локальная выдача сохраняется.
Общий размер одной порции остаётся до 48 элементов.

У своих материалов есть карточка, лайк, коллекции, пауза, скачивание оригинала
и удаление с подтверждением. Браузер с поддержкой Web Share Files может отправить
сам файл; иначе интерфейс предлагает скачать и отправить его вручную.
HTML-код встраивания использует относительное имя файла и инструкцию разместить
скачанный файл рядом со страницей: локальная blob-ссылка не выдаётся за публичную.

Размер загрузки не ограничен приложением. Возможности декодирования и свободное
место определяет браузер; при ошибке сохранения частичная запись не остаётся.
Проверки `node tests/loop.uploads.cjs` и `LOOP_ENGINE=webkit node tests/loop.uploads.cjs`
покрывают миграцию базы, все типы файлов, файл более 50 МиБ, сохранность после
перезагрузки, смешанную выдачу, скачивание, недоступность источника, изоляцию
аккаунтов и удаление связанных данных.

## Развёртывание через менеджер

Чистая установка использует `rwm install node --template 06-loop-archive` вместе
с обязательными параметрами ноды и сертификата. На существующей ноде применяется
`rwm disguise apply` с тем же ID. Оба пути устанавливают общие модули, версии
ресурсов и nginx-маршруты. Условия совместимости, CDN, XHTTP, WARP, Subscription
Page и откат описаны в [руководстве по развёртыванию](node-sites.md).

Сессия сохраняется после закрытия браузера. При первом открытии прежняя сессия
из хранилища вкладки переносится автоматически. Выход выполняется явно через интерфейс.
