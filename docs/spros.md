# Спрос — вопросы и ответы (`04-signal-works`)

Статическое приложение вопросов и ответов со своим оформлением. Идентификатор
шаблона сохранён для совместимости с `rwm disguise apply`. Интерфейс русский и
английский, содержимое источника остаётся на исходном языке. Вёрстка рассчитана
на телефон от 320 px, планшет и десктоп.

## Данные и действия

Гость читает актуальную ленту, пространства, поиск, страницу вопроса и
опубликованные ответы «Ответов Mail». Приложение читает анонимные
GET-маршруты веб-клиента:

| Маршрут сайта | Источник |
| --- | --- |
| `/_answers/mail/feed?limit=20[&pos=…][&space=…]` | `/api/topic/feed` |
| `/_answers/mail/spaces` | `/api/topic/spaces/top` |
| `/_answers/mail/search?text=…` | `/api/topic/search` |
| `/_answers/mail/question/{id}` | `/api/topic/question/{id}` |
| `/_answers/mail/answers/{id}?limit=50[&pos=…][&reply_id=…]` | `/api/topic/answers/{id}` |
| `/_answers/mail/profile/{id}/topics?limit=20&dir=0` | `/api/topic/profile/{id}/topics` |
| `/_answers/mail/profile/{id}/replies?limit=20&dir=0` | `/api/topic/profile/{id}/replies` |
| `/_answers/mail/profile/{id}/count` | `/api/topic/profile/{id}/content/count` |

Для следующих страниц профиля передаются `dir=1&pos=…`. Для ответов курсор
приходит в `params.last`, но передаётся как **`pos`**, без `dir=1`; вложенные
ветки используют `reply_id`. Профиль загружается отдельно от ленты, вопросы
и ответы имеют независимые состояния, курсоры и повтор после ошибки.

Общий счётчик обсуждения одинаков в ленте и вопросе, включает ответы и
комментарии, добавленные в этом браузере. Вложенные ветки загружаются автоматически вместе с родительскими ответами;
кнопка продолжения основного списка располагается под обсуждением. Закреплённые ответы
и пересекающиеся страницы объединяются по ID. Ошибка загрузки не означает
ноль ответов и не скрывает уже загруженные записи. Если источник завершил
список раньше заявленного общего числа, интерфейс сообщает об этом явно:
счётчик API не гарантирует доступности удалённых или скрытых записей.

Смена курсора продолжает ленту даже после страницы, целиком состоящей из
дубликатов или отфильтрованных записей. Повторившийся курсор останавливает
подгрузку, чтобы избежать цикла.

Используются анонимные маршруты веб-клиента, без гарантий стабильности API
и квот. Сайт не отправляет POST, cookies или данные локального
профиля в Mail. Сбои источника показываются прямо; последняя лента хранится
до семи дней и всегда помечается как сохранённая.

Локальный профиль открывает свои вопросы, ответы, комментарии и вложенные
ответы, голосование, сохранение и выбор лучшего ответа у собственного вопроса.
Публичные счётчики Mail не изменяются; локальные действия живут в IndexedDB
этого браузера. Несколько профилей одного браузера видят общую локальную доску,
но их голоса, сохранённое и личные данные разделены. На другие устройства
данные автоматически не переносятся. 
Пароли хэшируются Web Crypto PBKDF2-SHA256 с индивидуальной солью, 210000
итераций. Сессия хранится в `localStorage`. Это не серверная аутентификация:
владелец данных браузера может изменить их через инструменты разработчика.
Очистка данных сайта удалит локальные профили и обсуждения.

## Безопасность и права на содержимое

API-запросы идут через фиксированные GET-маршруты существующего nginx. У каждого
маршрута ограничены путь и параметры; произвольный адрес источника указать
нельзя. TLS upstream проверяется, cookies и Authorization пользователя не
передаются, `Set-Cookie` источника скрыт. Клиент ограничивает размер JSON,
время ответа и обрабатывает 429. Rich text превращается в обычный текст;
внешний HTML не исполняется. Изображения разрешены только с известных HTTPS
доменов; ссылки на источник составляются из числового ID. CSP запрещает
сторонние скрипты, стили, формы и фреймы.

Гостевой доступ к материалам не означает свободную лицензию на их
перепубликацию. По [соглашению Mail](https://help.mail.ru/legal/terms/otvet/ua/)
права на пользовательские материалы обычно остаются у авторов. Перед публичным
использованием за пределами личного просмотра следует отдельно определить
допустимый объём показа текста и изображений. Возможный безопасный режим —
краткая карточка со ссылкой на оригинал вместо полного текста.

## Установка и просмотр

Штатная установка обновляет файлы, управляемую конфигурацию nginx и инвентарь
одной транзакцией с резервной копией и откатом при ошибке:

```sh
sudo rwm disguise apply 04-signal-works
```

Обычный Live Server не создаёт маршруты `/_answers/mail/*`; без них внешняя
лента не загрузится. Для локального просмотра запустите из корня проекта:

```sh
python3 scripts/preview_answers.py
```

Если терминал открыт в родительской папке `Projects`, команда:

```sh
python3 remnawave-manager/scripts/preview_answers.py
```

Адрес по умолчанию — `http://127.0.0.1:5504/`. Скрипт раздаёт только каталог
сайта и выполняет те же ограниченные анонимные GET-запросы. Он не нужен в
production. Остановка — Ctrl+C.

## Проверки

```sh
PYTHONPATH=src python3 -m unittest \
  tests.test_packaging tests.test_answers_integration \
  tests.test_disguise_sites tests.test_morrow_integration -q
node tests/answers.browser.cjs
node tests/answers-pagination.browser.cjs
node tests/pagination.cjs
```

Браузерный тест использует установленный Chrome и `playwright-core` из
`tests/.tmp/node_modules`. Сетевые ответы Mail заменены фиксированными
данными; проверяются гостевая лента, регистрация, локальные вопросы и ответы,
комментарии и вложенность, лучший ответ, два профиля,
сохранение внешнего вопроса, пространства, перезагрузка, два языка, мобильная
ширина, восстановление после повреждённого состояния и отсутствие внешних записей.
Интеграционные Python-тесты проверяют допустимые маршруты, копирование
шаблона, миграцию nginx и откат. Конфигурация прокси отдельно проверялась
`nginx -t` на доступном nginx; реальную работу на целевом node и доступность
у российских провайдеров нужно проверять при развёртывании.

## Развёртывание через менеджер

Чистая установка использует `rwm install node --template 04-signal-works` вместе
с обязательными параметрами ноды и сертификата. На существующей ноде применяется
`rwm disguise apply` с тем же ID. Оба пути устанавливают общие модули, версии
ресурсов и nginx-маршруты. Условия совместимости, CDN, XHTTP, WARP, Subscription
Page и откат описаны в [руководстве по развёртыванию](node-sites.md).

Сессия сохраняется после закрытия браузера. При первом открытии прежняя сессия
из хранилища вкладки переносится автоматически. Выход выполняется явно через интерфейс.

Кнопка продолжения проверяет наличие новых записей в следующей порции,
а не только наличие указателя страницы. Проверенная порция кратковременно
сохраняется в памяти и используется при следующем нажатии. Пустые страницы
и повторы пропускаются; сбой сети оставляет возможность повторить запрос.
Общий модуль также используется в Line, Loop и комментариях Fokus.
